# 岗位交接（搜索端 → 投递端的中间区域）

本目录只允许以下固定文件，全部覆盖写、只保留最新一版，不另存历史、备份或按批次的副本（回滚用 git）：

| 文件 | 写入方 | 用途 |
|---|---|---|
| `工作簿全量.json` | 搜索组件 `json_excel_sync.py` | 唯一主数据；Excel 只由 `write` 从它写出，与 Excel 逐格对照 |
| `公司/<地区>/<公司>/公司.json` | 搜索组件 `company_store.py refresh` | 投递运行数据：公司编号、官网域名、官方岗位ID、志愿分组与顺序、城市选项（只存主表没有的字段） |
| `公司/<地区>/<公司>/登录*.json`、`表单定义*.json` | 投递组件 | 各站点登录配置与官方表单定义 |
| `投递批次.json`、`正向评审.html` | 搜索组件 `company_store.py forward` | 本轮交给投递端的岗位；用户确认（`forward-confirm`）后投递端才接收，确认后被改动即拒收 |
| `投递回传.json` | 投递组件 `application_closeout` | 每个岗位只留最新一条投递结果 |
| `反向评审.html` | 搜索组件 `company_store.py reverse` | 把回传结果逐行展示为“当前状态是X，更新状态是Y”；用户确认（`reverse-confirm`）后才写主表 |

流程：搜索与选岗写主数据 → `refresh` 生成公司文件 → `set-order` 记录用户给的志愿顺序 → `forward` 生成批次与评审页 → 用户确认 → 投递组件执行并回传 → `reverse` → 用户确认写回主表。上一批反向评审未完成前不能生成下一批。
