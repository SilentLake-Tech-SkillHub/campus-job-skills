# 数据建设与固定流程

## 唯一存放位置（只保留最新一版，覆盖更新）

| 信息 | 位置 | 写入方式 |
|---|---|---|
| 岗位行全部字段、投递状态 | `岗位交接/工作簿全量.json` 各地区表 | `json_excel_sync.py upsert / confirm / reset-rows` |
| 公司投递规则与名额 | 主数据 `投递名额` 表（每公司每范围一行） | `json_excel_sync.py set-quota-rules`，按公司整体覆盖 |
| 校招主链接、投递窗口 | 主数据 `校招主链接` 表 | `upsert` 同一行覆盖 |
| 校招计划清单 | 主数据 `校招计划` 表（不存投递限制） | 同上 |
| 字段与标签说明 | 主数据 `分类说明` 表 | `json_excel_sync.py set-sheet-rows` 整页覆盖 |
| 投递组件运行数据（companyId、官网域名、官方岗位ID、志愿分组、用户给定的志愿顺序、城市选项） | `岗位交接/公司/<地区>/<公司>/公司.json` | `company_store.py refresh` 按主表覆盖重建；志愿顺序用 `set-order` 记录用户原话 |
| 各站点登录配置、表单定义 | 同目录 `登录[@域名].json`、`表单定义[@域名].json` | 投递组件建档 |
| 当前投递批次与正向评审页 | `岗位交接/投递批次.json`、`岗位交接/正向评审.html` | `company_store.py forward / forward-confirm` |
| 本轮一次性投递需求 | `产品管理/user_applicaiton_requirements_temp.json` | `application_requirements.py set` 覆盖写入；forward成功后立即清空，完成时检查 |
| 投递结果回传与反向评审页 | `岗位交接/投递回传.json`、`岗位交接/反向评审.html` | 投递组件 `application_closeout`；`company_store.py reverse / reverse-confirm` |
| 状态变更确认 | `产品管理/投递状态变更确认.json`（每行只留最近一次） | 只由 `confirm` / `reset-rows` 写 |
| 用户求职目标与选岗规则 | `产品管理/求职目标.json` | 纠正时直接改写对应条目 |
| 运行配置与材料指针 | `产品管理/求职配置.md` | 直接改写 |

`岗位交接/` 下只允许上表里的文件；搜索与核验的过程文件放工作区以外的临时目录，结论写回上表位置后即删除。Hook 拦截在 `岗位交接/` 新建其他文件，以及在工作区写入名为历史/备份/快照/存档/上一版/副本的文件。禁止追加“旧结论/新结论/历史研究记录”，禁止按批次另起一份同类文件。

## 数据方向

主数据 `岗位交接/工作簿全量.json` 与 Excel 逐格对照；Excel 只给人看，AI 不读不改，只能由 `json_excel_sync.py write` 写出并读回。每次对话结束前若有未写入 Excel 的改动，必须展示逐格差异并问用户现在写入还是下一轮写入（`defer` 登记原话）。

## 搜索结果入表

1. 每个岗位一行：`岗位名称` 只写官网原名（不写“第N志愿”，不把多个岗位拼成一行）；`岗位链接` 必须是该岗位的官网详情页（不是首页、列表页、第三方招聘网站，也不与其他岗位共用）。打不开或内容对不上的链接不得入表。
2. 新岗位行用 `upsert` 写入，状态为空；随后 `propose` 给出“当前状态是空，更新状态是岗位待筛选”，用户确认后 `confirm`。
3. 公司规则只写“投递名额”表：`投递上限` 为整数或“公司未披露”，`是否分BU可平行投递` / `是否可以滚动投递` 只能是 是/否/公司未披露，没有明确结论就是公司未披露；`当前投递数量` 由脚本计算。
4. `备注` 只用于“用户例外保留：<原因>”，其余一律留空；`投递截止` 写日期或“公司未披露”。
5. 选岗由用户决定。用户选满某公司“公司总量”上限后，`propose/confirm` 会把同公司剩余“岗位待筛选”一并列为“岗位不符合用户要求”（名额收口），未选满前不得剔除。
