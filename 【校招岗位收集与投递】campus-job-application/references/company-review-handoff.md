# 公司交接：正向评审与反向评审

搜索端与投递组件之间只通过 `岗位交接/` 的固定文件交接（见 [数据建设与固定流程](storage-workflow.md)）。批次状态：空闲/已回写 → 等待正向评审 → 已交接 → 等待反向评审 → 已回写。

## 正向：主表 → 投递组件

1. `company_store.py refresh`：按主表覆盖重建 `公司/<地区>/<公司>/公司.json`，并给每个岗位定志愿分组：该公司“投递名额”表“公司总量”行的“是否分BU可平行投递”为“是”时按所属BU分组（BU未披露归“公司”），否则整家公司一组。
2. 志愿顺序：同一分组有多个待投递岗位时，向用户展示分组和岗位，由用户给出顺序；`company_store.py set-order --input <[{sheet,company,link|title,顺序}]> --quote "<用户原话>"` 记录（分组内不重复的正整数，同组一次给全；第1志愿已投递时本批可以从2起）。Agent 不替用户排顺序。
3. `company_store.py forward`：从[一次性需求表](application-requirements.md)读取本轮公司范围；空需求默认最新10家公司，保留各公司全部“岗位待投递”岗位。生成 `投递批次.json`（等待正向评审）与 `正向评审.html`并读回后立即清空临时需求；失败保留。链接、身份、已确认链接例外及志愿顺序继续由固定脚本核对，未通过的岗位在评审页“本批不交接”列出原因。
4. 把评审页给用户看；用户明确确认后 `company_store.py forward-confirm --quote "<用户原话>"`（登记原话与内容摘要，批次 → 已交接）。
5. 投递组件的 `role_queue_import` / `company_batch_create` 只读取已交接且确认后未被改动的批次；Hook 同样拦截未确认的批次。上一批未完成反向评审前不能生成下一批。

材料种类只在 `references/role-materials.json` 定义（主表列、分隔符、“明确没有”的写法、取值格式），key 与投递组件 `catalog/role-materials.json` 一致；新增材料两边各加一项。组批同时生成每岗位 `materials` 契约：推荐码原文、解析值、来源主表行链接/列/Hash与“有则必填”条件。没有代码与待核实分别标识，个人主档和公司配置不复制代码。正向确认再次对照主表，漏材料或来源变化拒绝确认。

确认按作用域保存：`confirmation.scopes.selection`（正向评审确认选岗）与 `confirmation.scopes.materials`（补充材料确认）各保留最新一条，互不覆盖；顶层 `userQuote/confirmedAt/contentSha256/scope` 是当前生效的门禁，即最近一次确认。确认后的任何局部变更都必须声明自己的作用域，只改该作用域字段，只让依赖它的冻结状态失效，并保留其他作用域的确认原话。

当前批次补充材料使用 `company_store.py amend-materials` 先预览；用户明确批准后以 `--expected-sha <预览原摘要> --quote "<用户原话>"` 执行。只补已确认岗位材料，不改变岗位、链接、顺序、批次ID或主表状态；覆盖原评审页。投递端随后用 `company_batch_refresh_materials` 更新原任务材料，保留原浏览器及未保存表单，旧冻结计划和完成核验必须重新生成。

## 反向：投递组件 → 主表

1. 投递组件 `application_closeout` 校验官网证据后把每个岗位的最新结果覆盖写入 `投递回传.json`（不改主表）。
2. `company_store.py reverse`：读回传，逐行给出“当前状态是X，更新状态是Y”（确认投递 → 岗位已投递；官网确认关闭 → 岗位失效/关闭），不确定、受阻、跳过的结果只列出不改状态；生成 `反向评审.html`，批次 → 等待反向评审。
3. 原样把变更给用户看；用户确认后 `company_store.py reverse-confirm --quote "<用户原话>"` 写主表（记确认台账）并清除已处理的回传。不确定或受阻的结果在用户处理前保留，重新导入时对应岗位受保护不重跑；用户处理后用 `--resolved <companyId|岗位ID>` 清除。只处理了部分岗位时，批次保持“进行中”，沿用原岗位与确认摘要；全部批次岗位都已处理才变为“已回写”，才能生成下一批。批次 `progress` 只存当前执行进度，不进入岗位/材料确认摘要；不能借此更改岗位、顺序或材料。

选岗、去留、志愿顺序 100% 由用户决定；Agent 只展示与建议，不按名额提前淘汰任何符合要求的岗位。
