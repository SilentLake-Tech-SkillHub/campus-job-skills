# 数据文件保护边界

本文件是数据文件保护规则的唯一文字来源；`SKILL.md`、工作区 `AGENTS.md` 和 Hook 注入文字只引用本文件。

数据保护直接消费框架已有的 `status_sync_hook.protected(cfg)` 清单。清单从工作区登记配置取得工作簿、主数据、确认台账、标签组、公司目录等路径；不建立另一份清单文件，不按扩展名识别业务数据。清单中的目录本身及其子项都在范围内。路径按本次工具的工作目录解析为绝对路径并解析符号链接，不能仅按文件名比较。

网申个人主档也由同一清单保护：路径优先读取部署环境 `RECRUITING_PROFILE_JSON`，其次读取配置 `profileFile`，缺省为工作区的 `产品管理/网申个人信息主档.json`。可读取，编辑器、重定向、复制覆盖和删除不得直接改写；资料更新走投递 MCP 的事实录入、映射等固定工具。业务授权仍只走投递组件的 `scripts/business-authorization.mjs`，按真实脚本路径识别，不信任同名外部脚本；复合命令中的重定向继续检查。既有模板、冻结计划和业务授权取值均不因加入保护而改变。

| 登记对象 | 规则 |
|---|---|
| 配置登记的工作簿 | 不直接读取、改写、移动或删除其内容。固定同步入口按配置中的实际脚本路径识别；命令中提到脚本名不构成授权。 |
| 其他登记数据文件与目录 | JSON 可以读取。写入、删除须经过框架固定写入入口；无法确定的访问在涉及登记对象时拒绝。 |
| 清单外文件 | 不由本项目数据保护规则接管。发现零散数据只报告，不为其追加兼容规则。 |

工作区主数据是 `岗位交接/工作簿全量.json`，AI 需要表格数据时读取它。Excel 只由配置登记的 `json_excel_sync.py write`（MCP `recruiting_json_write_excel`）写出；主数据、确认台账、标签配置和公司目录也只经框架各自的固定写入入口更新。

**数据保护不处理任何 Git 命令，不区分 Git 子命令。** Git 是否触及组件源码，由原有组件软锁独立判断；数据规则放行不能覆盖软锁拒绝。复合命令中 Git 之外的命令，以及 Shell 自己执行的重定向、命令替换，仍检查其实际数据目标。

纯文本问答和发消息不做文件拦截，包括 Codex 问答/消息工具及 Claude 的 `AskUserQuestion`、`SendUserMessage` 及 DSH 的 `todo_write`、`todo_read`；工具名称支持命名空间前缀。携带实际文件或附件参数时仍按文件操作检查。代码补丁只检查真实补丁文件头，编辑工具只检查真实目标参数，正文中的文件名和示例不作为实际目标。

`jq`、`wc`、`diff` 按读取输入文件处理：可以读取登记 JSON，不能读取登记工作簿；Shell 重定向仍单独检查。`find` 不在无条件只读名单中：普通枚举文件名可以执行；`-delete` 按搜索根目录及其子项的删除处理，`-exec`、`-execdir`、`-ok`、`-okdir` 涉及登记对象时按无法确定的文件操作拒绝，执行参数中明确提及的登记对象也检查。`-fprint` 等输出文件动作按写入处理，`-files0-from` 按读取处理。

已知文件工具、Shell 命令及内联程序按字面参数提取目标。解析失败或工具未知，且涉及清单中的路径时，拒绝并说明规则名、Hook 源文件位置、识别失败原因和正确操作入口。不涉及清单对象的未知调用不因文件后缀被拦截。Hook 是工作流防误操作机制，不是任意脚本的运行时文件系统沙箱；本轮不展开通配符或推导管道传递的路径，也不能据此声称覆盖计算、编码或外部脚本内部产生的所有文件访问。

组件软锁的授权识别、开关、路径范围、Git 处理及原有解析函数不在本轮修改范围。业务标签确认、正反向评审、提交授权和写入同步提醒继续独立生效。

回归测试使用 `scripts/fixtures/data_protection_events.json` 的固定事件样例，通过新 Python 子进程调用实际 Hook。覆盖三个宿主输出格式及 DSH 事件封装、各宿主真实工具名、Git、纯文本、`find` 动作、JSON 只读命令、登记目录、相对路径和符号链接、未知调用、脚本名诱饵、真实同步入口及软锁独立拒绝。

## 共享规则依赖

文字工具及文件参数的唯一定义由投递组件hooks/tool-arguments.json维护，依赖版本、内容指纹及源路径声明于component-dependencies.json。component_dependencies.py统一解析；工作区安装可直接读取相邻的已安装投递组件，独立安装通过RECRUITING_TOOL_ARGUMENTS_FILE指定原仓库的规则路径，或在声明的checkoutPath检出固定版本。安装和CI先运行component_dependencies.py check。不得复制规则文件、维护第二份列表或放宽缺依赖时的保护行为；规则变更须更新依赖声明并验证两个消费者。

## 组件维护授权的宿主答复

普通回复走宿主UserPromptSubmit并绑定会话。转述的编号、项目符号选项及其缩进说明不参与授权或撤回识别，独立写出的明确批准照常处理。Codex异步卡片还须从同会话的宿主会话记录核对真实问答请求、题目位置和标题。卡片标记随现有批准记录原子保存，重复答复不续期，撤回后也不能靠重放恢复。没有明确会话ID或无法核对卡片请求时，Hook报告未登记。Agent从一开始对只提供工具结果的宿主用普通聊天收集授权。授权记录由Hook写入，后续PreToolUse独立读取并拒绝带选项标记的历史误写记录。
