## 2.1.10 · 门禁注入按工作区生效

- 用户决定（2026-11-15，投递任务单 C37）：本改动保留并登记；原话：“Hooks应该是对这个项目生效，跨项目不生效”“保留并登记（推荐）”。
- 起因：Hook 在 DSH 全局 profile 里挂载，任意项目的会话都会收到投递门禁注入，收尾时还会因本工作区有待写单元格被 block，导致别的项目把无关改动当成自己的待办。
- 修改：`status_sync_hook.py` 在解析事件后按宿主 payload 的 cwd 判断，会话不在本工作区时直接返回空对象，不注入规则、不做收尾阻断；宿主没带 cwd 时按本工作区处理。
- 保留：`PreToolUse` 的数据文件写入保护不按工作区分流，任何会话绕过固定入口改写登记文件仍被拒绝。
- 验收：面部Keep 会话的 UserPromptSubmit、Stop 均返回空；本工作区仍注入完整规则；从外部会话尝试改写 `岗位交接/工作簿全量.json` 仍被 deny。
- 同一规则：`application_requirements.py` 的需求入口 Hook 在会话不在本工作区时不注入、不写本项目需求状态；宿主没带 cwd 时按本工作区处理。
- 测试：`test_status_sync_hook.py`、`test_application_requirements.py` 各新增跨项目用例，两文件 71 项通过。

## 2.1.8 · C9 组件维护授权识别

- 普通授权使用宿主UserPromptSubmit和真实会话ID。明确的非用户来源、通用工具结果和缺失会话ID不能生成授权。
- 转述的编号或项目符号选项及其缩进说明不参与授权或撤回识别。单独写出的明确批准照常处理。历史记录的原话带有选项标记时，权限检查忽略该记录。
- Codex异步卡片在宿主会话记录中核对同一会话、工作区、原始调用ID、问题位置与标题。卡片防重放标记和最近授权写入同一文件，保留加锁、原子替换、保存后读回。撤回清除有效授权，仍阻止同一卡片复用。
- Claude Code / DSH 的普通聊天沿用原入口。结构化工具答复需以宿主可核实的真实答复来源为接入依据。DSH旧桥接传入的普通消息仍依赖宿主提供正确的用户事件。
- 验收包含普通回复、同会话放行、跨会话、来源错误、请求过期、重复答复和撤回后重放。真实宿主卡片验收按工作区任务单记录。
